# 3DGS 重建质量归因与单变量改进计划

> 原始计划日期：2026-09-20  
> 整理日期：2026-09-28  
> 状态：待执行；本文档不是实现、远端实验或默认变更授权  
> 适用项目：Image3D-SceneGraph  
> 权威边界：`codex.md` 仍是项目唯一 plan of record；本文档仅定义下一轮研究工作的可执行方案  
> 论文背景：`docs/3dgs-research-architecture-reference.md`

---

## 1. 目标

下一阶段不接入第三个训练器，也不把多篇论文的方法一次性叠加到现有系统中。计划保留当前 **COLMAP＋gsplat＋Project/MCMC 对照**，先回答一个更基础的问题：

> 当前不满意区域主要受几何／相机误差、训练覆盖不足、增密机制不足，还是外观与采集条件限制？

完成归因后，只选择一个证据最充分的因素做单变量 A/B。目标不是追求某个汇总指标的偶然提升，而是：

1. 在预先冻结的坏区域中获得可确认、可重复的改善；
2. 不损伤原本正常的区域；
3. 不新增明显孔洞、漂浮物、遮挡跳变或视角间闪烁；
4. 明确记录质量收益对应的时间、显存和 Gaussian 数量成本；
5. 让另一名执行者仅凭冻结合同、代码提交和输入资产即可复跑。

## 2. 当前证据与尚不能下的结论

### 2.1 已有观察

现有同源输入、同相机条件下的 Validation 对照显示：

- 窗边椅子的固定视角中，Project 存在明显灰白雾化；MCMC 显著恢复了主体对比度；
- MCMC 仍没有恢复椅背、窗帘等局部细节；
- 低机位视角中的椅脚、轮子和地毯纹理，在两个训练器中都存在结构模糊或细节损失；
- 因此，至少一部分缺陷与训练方法有关，但两个训练器也共享尚未解决的质量上限。

### 2.2 不能据此声称

当前证据不能证明：

- Project 的雾化由 `recovery-prune` 单独造成；
- MCMC 的改善由某一个超参数单独造成；
- 增加 Gaussian 上限或训练迭代一定能恢复细节；
- Validation 外观改善等于几何更准确；
- 手机视频的电子防抖、滚动快门或自动曝光已经被确认是根因；
- AirSplat、VCR-GauS、AbsGS、PUP 等论文方法可以作为插件直接接入现有训练器。

Project 与 MCMC 同时改变了优化策略、增密／重定位、正则和容量行为，现有对照只能用于发现问题，不能替代单变量因果实验。

## 3. 范围与明确非目标

### 3.1 本轮范围

本轮只包含：

1. 冻结少量固定区域和现有证据；
2. 完成一次有界、以现有产物为主的质量归因；
3. 根据归因结果，从两个主方向中选择一个；
4. 为该方向实现并运行一个单变量 A/B；
5. 按预声明门禁决定停止、复核或进入后续研究。

### 3.2 本轮不做

- 不接入第三个训练器；
- 不重写为 LongSplat、NopeRoomGS 或其他完整系统；
- 不同时修改相机、几何监督、采样、增密、剪枝和训练预算；
- 不把 navigation 作为本轮优化目标；它最多作为几何退化的辅助检查；
- 不运行或读取 Test；
- 不下载未经审计的新权重，不在 Job 运行时下载依赖；
- 不覆盖已完成 Job、原始模型、冻结 replay 或既有报告；
- 不根据少量挑选截图宣称整体提升；
- 不修改生产默认，也不把 research-only 分支描述为已推广能力。

## 4. 论文复现与项目借鉴的命名规则

为避免把“受论文启发”写成“复现论文”，所有实验必须选择以下一种身份并写入合同。

| 身份 | 使用条件 | 允许的表述 |
|---|---|---|
| 忠实复现 | 固定论文版本、官方代码 commit、依赖、权重、数据处理、训练配置和指标；解释无法完全一致的部分 | “复现／部分复现某论文” |
| 方法级移植 | 方法核心定义与原文一致，但接入当前数据和训练框架；列出所有接口差异 | “移植某论文的方法组件” |
| 论文启发的项目实验 | 只借鉴原则或局部机制，未满足原论文完整定义 | “受某论文启发”，不得称为复现 |

本计划中的两个近期候选默认都属于**论文启发的项目实验**：

- 高置信度几何监督：受 VCR-GauS、NopeRoomGS、Deep Gaussian from Motion 启发；
- 细节增密：可评估 AbsGS 的梯度累积原则，但只有完整核对原文与官方实现后，才能声称方法级移植。

AirSplat ROM 与 PUP 只属于后续阶段，不能提前写成已复现功能。

## 5. 全程冻结的可复现合同

任何代码修改或远端运行之前，必须先生成一份不可覆盖的实验合同。合同至少包含：

### 5.1 输入与版本

- 输入视频／图片清单及 SHA-256；
- 接受的 COLMAP 模型、相机、稀疏点、去畸变数据和 replay 哈希；
- Project/MCMC 基线模型、checkpoint、export 和 manifest 哈希；
- 代码完整 SHA；
- Python、PyTorch、CUDA、gsplat、COLMAP 及驱动版本；
- GPU 型号、数量和显存；GPU 信息必须在实际运行前重新采集；
- 随机种子及确定性设置。

### 5.2 数据使用边界

- **Train**：允许用于优化、训练拟合分析和几何支持分析；
- **Validation**：仅用于比较和选择，不反向调参；
- **Test**：不加载、不渲染、不读取指标和图像；
- 固定区域必须在查看候选实验结果之前冻结；
- 若新增区域，旧结果不能用于决定该区域的位置，新增区域必须单独标记为探索性证据。

### 5.3 单变量约束

每个 A/B 只能改变一个明确 leaf，并固定：

- 相机与归一化；
- Train/Validation 划分；
- 初始化和 replay；
- renderer 与图像尺寸；
- 训练视图采样预算；若预算本身是变量，则固定其余所有因素；
- densify/clone/split/prune/reset 策略中不属于该 leaf 的部分；
- seed；
- checkpoint 选择规则；
- 导出和评估脚本。

如果实现迫使两个因素同时改变，则不得将结果解释为其中任一因素的单独收益。

### 5.4 输出与失败保留

- 每轮使用新的独立输出目录；禁止覆盖已有产物；
- 保存启动命令、解析后配置、环境摘要、输入哈希、stdout/stderr 和退出码；
- OOM、超时、NaN、依赖缺失和质量门禁失败必须原样保留；
- fallback 默认不允许；如合同明确允许，fallback 结果也不能计为候选方法通过；
- 训练报告同时记录耗时、峰值显存、峰值 Gaussian 数和最终 Gaussian 数。

## 6. 阶段 0：冻结基线与观察区域

### 6.1 固定区域

至少冻结以下四类区域：

| 区域 | 用途 | 当前已知现象 |
|---|---|---|
| 窗边椅子 | 方法相关伪影 | Project 雾化明显，MCMC 改善对比度 |
| 低机位椅脚／轮子／地毯 | 共同结构与细节问题 | Project 与 MCMC 都模糊 |
| 桌面／窗帘 | 纹理、薄结构与遮挡边界 | 用于区分欠拟合、几何错位和外观问题 |
| 正常墙角或稳定区域 | 负向控制 | 候选方法不应破坏原本正常区域 |

每个区域必须记录：

- 场景、帧／相机 ID；
- Train 或 Validation 身份；
- 归一化像素框或多边形；
- 选择理由；
- 对应原始输入、Project 和 MCMC 图像哈希；
- 至少一段相邻视角序列，用于检查闪烁和遮挡跳变。

“2907”“36”等既有视角可作为候选，但必须以实际 manifest/camera ID 和图像哈希固化，不能只保留肉眼编号。

### 6.2 基线清单

冻结：

1. 当前 Project v7 基线；
2. 当前 MCMC 对照；
3. 原始输入图像；
4. 相机、SfM 和训练日志；
5. 已有 Train/Validation 渲染；
6. 可用的采样、densification、opacity、scale 和 Gaussian 数量时间序列。

如果任一基线缺少决定性配置、哈希或切分身份，阶段 0 不通过，先补证据，不启动新训练。

### 6.3 阶段 0 交付物

- `contract.json`：完整冻结合同；
- `roi.json`：固定区域、相机和坐标；
- `inventory.json`：输入与现有产物哈希；
- `baseline-contact-sheet/`：输入、Project、MCMC 的同视角无后处理对照；
- `baseline-summary.md`：只陈述观察，不做未经验证的因果结论。

## 7. 阶段 1：有界质量归因

阶段 1 原则上只读取现有产物，不修改模型、不运行新训练。若现有证据不足，只允许生成必要的 Train/Validation 渲染或只读统计，并将新增工作写入合同。

### 7.1 每个区域回答五个问题

1. **输入是否包含目标细节？**  
   检查原始帧清晰度、曝光、运动模糊、反光、透明／细网结构及有效观测数量。

2. **Train 是否已经拟合该细节？**  
   对比邻近 Train 输入与同相机渲染。Train 也模糊通常更支持优化覆盖或表达／增密问题；Train 清楚但 Validation 差更支持视角覆盖、几何或外观泛化问题。

3. **相机和几何支持是否可信？**  
   复用已有 pose health、reprojection、track support、观测角度、稀疏点和深度一致性证据。不得只靠 RGB 观感判断几何正确。

4. **问题是否跨视角保持一致？**  
   检查相邻视角中缺陷是固定在三维位置、随视角漂移、只在遮挡边界出现，还是只随曝光／反射变化。

5. **Project 与 MCMC 的差异指向什么？**  
   记录改善和回退区域，但不把多因素训练器对照直接当作单变量因果证据。

### 7.2 最小统计

每个固定区域至少报告：

- Train 与 Validation 身份及有效观测数；
- 输入清晰度／曝光异常的只读证据；
- Project、MCMC 的 ROI PSNR/SSIM（有合法参考时）及逐视角差值；
- 未获批准的 LPIPS 继续标记为 `not_run`，不得用其他指标代替后仍称 LPIPS；
- SfM track 支持、重投影误差和视角分布；
- 若已有可信深度：尺度对齐后的跨视深度残差与置信度覆盖；
- Gaussian 局部数量、opacity/scale 分布和可见贡献；
- 相邻视角的孔洞、漂浮、遮挡跳变和闪烁检查；
- 全局 Validation 分布作为控制，不能只报 ROI。

### 7.3 归因分类

| 主要观察 | 首选归因 | 下一步 |
|---|---|---|
| 输入清楚、几何支持充分，但 Train 也持续模糊 | 训练覆盖或细节增密不足 | 候选 B |
| Train 清楚，Validation 差，且邻近 Train 支持弱 | 视图覆盖／泛化问题 | 暂不增加迭代；先复核采样与覆盖 |
| 多视角中结构位置不一致，且相机／点／深度证据异常 | 相机或几何约束不足 | 候选 A，或先停止并修复上游几何 |
| 大平面深度不稳、自由空间出现遮挡，可信深度证据可用 | 表面几何约束不足 | 候选 A |
| 缺陷主要随曝光、反射、玻璃或动态物体变化 | 外观／采集条件 | 不进入 A/B，另立外观问题计划 |
| Project 改善而 MCMC 回退，或反之，但缺少可分离机制 | 训练器复合差异 | 不做因果结论，继续只读审计 |

### 7.4 阶段 1 决策门禁

阶段 1 结束时必须输出：

- 一个**主要瓶颈**；
- 至多一个**次要替代解释**；
- 支持与反对该判断的证据；
- 一个拟议单变量 leaf；
- 为什么不选择另一个候选。

如果证据不能区分候选 A 和 B，则结论必须是“归因不足”，本轮停止。不得为了继续开发而同时实现两个方向。

## 8. 阶段 2A：候选 A——高置信度几何监督

### 8.1 进入条件

只有同时满足以下条件才进入：

- 阶段 1 显示结构／表面问题而非单纯外观问题；
- 相机总体通过现有健康门禁；若相机不可信，应先修上游，不能让 Gaussian 损失吸收位姿错误；
- 存在可审计的教师深度或几何证据；
- 教师证据已完成尺度对齐、置信度过滤和跨视一致性检查；
- 遮挡边界、玻璃、反光、细杆／细网结构能够被排除或降低权重。

### 8.2 最小实验

首轮只改变一个 leaf：**增加一种高置信度深度监督**。

A/B 两臂：

- A0：冻结的现有基线；
- A1：A0＋高置信度深度损失。

其余保持一致。首轮禁止同时加入：

- 法线损失；
- 平面损失；
- 相机优化；
- opacity rating；
- 新的 densification 策略；
- 新的剪枝或后处理。

### 8.3 方法边界

- 教师深度不是真值；损失必须记录教师置信度、尺度对齐和自身跨视误差；
- 不能在不确定区域强制几何收敛；
- 如果实现只使用普通深度差，就必须称为项目深度监督实验，不能称为完整 VCR-GauS 复现；
- 原论文涉及的交点深度、法线构造或专用 CUDA 若未实现，必须在报告中明确列为差异。

### 8.4 通过条件

A1 只有同时满足以下条件才可进入复验：

1. 预声明结构问题区域改善超过阶段 0 冻结的最小有效差异；
2. 正常控制区域没有超过容忍度的回退；
3. 全局 Validation 分布无系统性回退；
4. 没有新增明显孔洞、薄结构消失、自由空间遮挡或视角闪烁；
5. 资源成本未超过合同上限；
6. 所有结果可以从冻结合同重跑并得到一致结论。

若只改善 RGB 指标而几何证据变差，不能判为通过。

## 9. 阶段 2B：候选 B——训练覆盖与细节增密

### 9.1 进入条件

只有阶段 1 同时显示以下特征才进入：

- 原始输入中的目标细节清楚；
- 相机与几何支持没有主要异常；
- Train 视角本身仍未充分拟合细节；
- 问题不是仅由曝光、反射、玻璃或动态内容解释。

### 9.2 先完成预算审计

在改训练器之前，报告：

- Train 相机数；
- 每个相机实际被采样次数的分布，而不只使用理论均值；
- densification 停止前每个相机的采样次数；
- 固定坏区域在训练中的有效可见次数；
- clone/split/prune/reset 的时间线；
- 梯度统计是否可能发生正负抵消；
- Gaussian 上限是否实际成为约束；
- 后期追加步数带来的有效采样量，而不只报告“又训练了多少步”。

例如，在 3,016 个 Train 视角、每步消费两个视角的前提下，30k 步的理论平均覆盖约为每视角 19.9 次；若 densification 在 15k 停止，则其前理论平均约为 10 次。实际计划必须使用日志中的真实采样分布核对，不能只凭该理论值下结论。

### 9.3 根据审计只选一个 leaf

| 证据 | 可选单变量实验 |
|---|---|
| 视角采样严重不均，坏区域有效曝光不足 | 在相同总视图样本预算下，只改变采样策略 |
| 所有视角覆盖尚可，但细节梯度存在方向抵消证据 | 只改变 densification 梯度累积语义，例如核对后的 AbsGS 式绝对梯度 |
| 训练与 densification 都明显过早结束，其他机制无异常 | 只增加训练／densification 预算，并明确资源代价 |
| Gaussian 上限提前饱和且局部仍欠表达 | 只改变容量上限；不得同时改增密规则 |

不得把“延长训练＋提高上限＋AbsGS＋改变剪枝”组合成一个实验。

### 9.4 AbsGS 命名边界

仅打开一个 `absgrad` 布尔值，不自动等于完成 AbsGS。若选择该方向，实施前必须逐项核对：

- 论文与官方代码版本；
- 绝对梯度的定义和累积位置；
- split/clone 判定；
- threshold、采样和剪枝的配套语义；
- 当前 gsplat 版本的接口差异。

未完整满足时，报告名称应为“AbsGS 启发的绝对梯度消融”，不能写成“复现 AbsGS”。

### 9.5 通过条件

B1 只有同时满足以下条件才可进入复验：

1. Train 固定坏区域的细节拟合有预声明改善；
2. 改善在对应 Validation 邻近视角中仍存在，而非只记忆 Train；
3. 正常控制区域及全局 Validation 无系统性回退；
4. 没有新增高频噪声、漂浮物、闪烁或异常细小 Gaussian；
5. Gaussian 数、训练时间和显存增长在合同上限内；
6. 若只是增加预算，结论明确写成质量—资源权衡，而不是算法创新。

## 10. 最小有效差异与复验规则

具体数值阈值不能在看到候选结果后制定。阶段 0 必须根据以下证据之一冻结阈值：

1. 同一基线的重复 seed 波动；或
2. 已有可比基线之间的逐视角自然波动；或
3. 对完全确定的渲染流程，使用明确的数值容差并把视觉门禁单列。

建议使用两级结论：

- **机制有效**：一个冻结场景、一个 seed 的配对 A/B 通过所有预声明门禁；只能说明值得复验；
- **可重复候选**：至少增加一个独立冻结场景或第二个预声明 seed，方向和主要区域结论一致；只有达到此级别，才允许讨论写入 `codex.md` 或推广默认。

单场景、单 seed、单个截图不能支持项目级推广。

---

## 11. 阶段 3：候选有效后再做清理或压缩

阶段 3 不属于本轮默认执行内容，必须另行批准。

### 11.1 AirSplat 启发的清理

适用前提：已经证明存在不可靠遮挡 Gaussian，且主要结构／细节问题已得到处理。

顺序：

1. 先做连续 rating 只读审计；
2. rating 必须扣除教师自身误差，而不是直接使用 `|gaussian_depth - teacher_depth|`；
3. 至少两个冻结场景表现出可重复区分度后，才做固定拓扑 opacity-only 派生；
4. 第一轮不同时加入位置修正；
5. Original 保持不可变。

该方向用于清理不可信贡献，不用于补回缺失的椅脚、纹理或结构。

### 11.2 PUP 启发的压缩

适用前提：质量已经稳定，目标转为模型大小、显存或交互效率。

顺序：

1. 先在较小冻结场景或 Gaussian 子集上 profile Fisher/Hessian 成本；
2. 先输出 importance 分布，不立即剪枝；
3. 与几何 rating 保留为两个独立维度，不发明未经验证的综合分数；
4. 只有资源可行且区分度通过后，才另行批准分阶段 prune/refine。

PUP 是质量—效率权衡，不是结构修复方法。

## 12. 统一验收矩阵

每个 A/B 报告必须同时覆盖以下维度：

| 维度 | 必须报告 |
|---|---|
| 外观 | 全局及 ROI 的逐视角 PSNR/SSIM、改善／回退视角数量、接触表 |
| 几何 | pose health、可用的深度／点／表面一致性、自由空间异常；不得宣称公制精度 |
| 稳定性 | 相邻视角中的孔洞、遮挡跳变、漂浮物和闪烁 |
| 局部目标 | 所有冻结坏区域和正常控制区域，不能只展示最佳案例 |
| 资源 | wall time、峰值 GPU 显存、峰值／最终 Gaussian 数、产物大小 |
| 可复现性 | 代码 SHA、输入哈希、配置、seed、环境、命令、退出码和输出哈希 |
| 未运行项 | 明确列为 `not_run`，不得省略或用其他指标冒充 |

验收结果只能是：

- `PASS_FOR_REPLICATION`：进入独立场景／seed 复验；
- `HOLD_INCONCLUSIVE`：证据不足，停止扩展；
- `FAIL_QUALITY`：质量或几何门禁失败；
- `FAIL_RESOURCE`：时间、显存、容量或稳定性超限；
- `FAIL_REPRODUCIBILITY`：配置、哈希、切分或证据不完整。

`PASS_FOR_REPLICATION` 不等于默认推广。

## 14. 执行顺序、授权点与停止条件

### 14.1 执行顺序

1. **冻结合同和 ROI**  
   验证：哈希、切分、相机 ID、区域坐标和现有基线齐全。

2. **完成只读归因**  
   验证：每个区域回答五个问题，并输出一个主要瓶颈。

3. **提交候选选择说明**  
   验证：只选择 A 或 B，并明确唯一 changed leaf、资源上限和成功／失败阈值。

4. **获得单独授权后实现最小改动**  
   验证：最小测试通过，代码差异只覆盖该 leaf，不改变默认。

5. **获得单独授权后运行一个配对 A/B**  
   验证：不读取 Test，不覆盖产物，完整保存失败和资源证据。

6. **按预声明门禁给出结论**  
   验证：报告包含全局、ROI、控制区域、稳定性和资源，而不是只展示最佳图片。

7. **仅在 `PASS_FOR_REPLICATION` 后提议复验**  
   第二场景／seed、默认推广、AirSplat 清理或 PUP 压缩都需要新的明确授权。

### 14.2 立即停止条件

出现以下任一情况即停止当前方向，不继续堆模块：

- 无法确认 Train/Validation/Test 身份；
- 输入、相机、模型或 replay 哈希不完整；
- A/B 不止改变一个因素；
- 主要问题被确认来自上游坏相机或数据采集，而候选方法只能掩盖它；
- 候选只改善一个挑选截图，固定区域或全局分布不支持；
- 出现系统性孔洞、薄结构消失、闪烁或几何退化；
- 资源超出合同上限；
- 需要临时读取 Test、修改生产默认或覆盖旧产物才能继续。

## 15. 当前建议

当前最合理的下一步不是继续接论文模块，而是先执行阶段 0 和阶段 1：

> 用窗边椅子、低机位椅脚／地毯、桌面／窗帘和一个正常墙角组成冻结区域集，把输入、Train、Validation、Project/MCMC 对照以及几何支持放到同一份归因报告中。

只有归因明确后，才在以下两个方向中选择一个：

- **候选 A：高置信度几何监督**——优先解决跨视结构、平面和自由空间不稳定；
- **候选 B：训练覆盖与细节增密**——优先解决输入清楚、几何可信但 Train 仍欠拟合的细节。

在结构和细节质量稳定之前，不优先做 AirSplat opacity 清理或 PUP 压缩。它们分别解决不可信贡献和模型效率，不能替代当前的根因归因。
