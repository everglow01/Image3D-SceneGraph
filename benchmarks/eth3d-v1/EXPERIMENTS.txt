Registration-gap diagnosis (B1)
-------------------------------
Evidence source:
outputs/benchmarks/eth3d-v1/pipes/colmap_vggt_points/reconstruction/
  colmap_vggt/database.db

All 14 images were feature-extracted and exhaustively matched. The three unregistered
images have substantial SIFT feature counts, so extraction is not the bottleneck:
- DSC_0637.JPG: 1744 features
- DSC_0646.JPG: 3366 features
- DSC_0647.JPG: 3049 features

Their verified two-view geometry is sparse and largely isolated from the 11-image model:
- DSC_0637.JPG: 136 inliers with DSC_0638.JPG, 60 with DSC_0645.JPG; all other
  registered-image pairs have zero verified inliers.
- DSC_0646.JPG: 88 inliers with DSC_0643.JPG; all other registered-image pairs have
  zero verified inliers.
- DSC_0647.JPG: 109 inliers with DSC_0643.JPG, plus 25 or fewer with several images.

COLMAP first built the 11-image component, then initialized a separate component using
DSC_0647.JPG and DSC_0646.JPG. It attempted to add DSC_0643.JPG to that component twice
and failed, then found no further viable initial pair. The chosen output remains the
11-image component (1146 sparse points, 0.749424 px mean reprojection error).

Conclusion: the immediate failure is insufficient verified geometric connectivity between
these three images and the main SfM component, not lack of image features. The next B2
experiment must vary only COLMAP matching/registration settings while holding VGGT,
fusion, RGB-only inputs, seed, and the ETH3D evaluation protocol constant.

Per-frame confidence percentile ablation — strict paired multi-scene result
-------------------------------------------------------------------------
Status: mixed; retain as experimental mode, do not replace the global default
Date: 2026-07-22
Configuration ID: confidence_scope_paired

Hypothesis: confidence values from independently inferred VGGT windows are not calibrated on
one absolute scale, so applying the frozen 50th percentile separately to each frame could
preserve useful views that a pooled global threshold suppresses. Reconstruction remained
RGB-only; ETH3D reference cameras and scans were used only after both point clouds existed.

A first full-pipeline run showed promising results, but its independently rerun COLMAP camera
solutions differed from the historical baselines. Those scores were not used for attribution.
The final ablation therefore generated `global` and `per_frame` point clouds from the same
in-memory COLMAP solution, VGGT depth/confidence maps, sparse depth scales, covisibility graph,
consistency thresholds, cap, and seed. Both alternatives used the same exported cameras and
therefore exactly the same evaluation Sim(3). The only changed behavior was confidence scope:
- global: pool all valid confidence values and apply one 50th-percentile threshold to every
  source and target frame (frozen baseline behavior);
- per_frame: derive each frame's 50th-percentile threshold from its valid non-padding canvas,
  use the source threshold for candidate selection, and the target threshold when validating
  a cross-view projection.

Frozen scene settings were retained: `pipes` used its accepted B2 registration thresholds;
`terrains` and `delivery_area` used B1; all used sequential VGGT groups, batch size 4, points
fusion, max 2000000 points, CUDA, and seed 42. No percentile or geometry threshold was changed
between scenes or after seeing official scores.

random draws. Sorting accepted points along a 21-bit-per-axis Morton space-filling curve and
selecting the midpoint of each equal-mass rank stratum should reduce random spatial holes and
clumps while preserving the reconstruction's empirical point-density distribution. The policy
uses only reconstructed XYZ coordinates, returns exactly the same point budget, and never reads
ETH3D reference cameras, scans, alignment, or evaluator scores.

byte-compatible with the previous cap implementation.
